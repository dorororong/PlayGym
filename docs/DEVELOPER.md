# PlayGym 개발자 문서

소개는 [README](../README.md). 이 문서는 구조·명령·명세와 다른 점·학습 실험 기록을 담는다.
명세: `PlayGym  — 강화학습 전용 블록코딩 게임환경 제작 툴 명세서.md` (저장소 루트)

## 실행

```bash
npm install
npm run dev          # http://localhost:5173 — 블록 편집기 + 게임 화면 + 관찰 패널
npm test             # 엔진·센서·결정론·런타임·템플릿 테스트 (Vitest, Node)
npm run bench        # headless 성능 (목표: 객체 50 + 라이다 16광선에서 5,000 step/s 이상)
npm run templates    # src/templates/sources.ts → src/templates/*.json 재생성
npm run build        # dist/ 정적 빌드 (정적 웹 서버로 배포. file:// 로 열면 학습 Worker 가 막힌다)
npm run train -- dino            # headless 학습 (예제 이름 또는 project.json)
                                 #   --algo ppo|dqn|reinforce|qtable --steps --skip --lr --hidden 64,64 --act relu --bins 6 --seed --out
npm run experiment -- --games pong,ski --algos ppo,dqn --seeds 2 --name 폴더   # 학습 가능성 실험 → experiments/<폴더>/
```

## Node 에서 환경으로 쓰기 (headless)

```ts
import { createEnv } from './src/engine/env';
import dino from './src/templates/dino.json';

const env = createEnv(dino);              // 학생이 저장한 프로젝트 JSON 도 그대로 된다
env.actionSpace;                          // { n: 2, names: ['none', 'up'] }
env.observationSpace;                     // { shape: [3], labels, low, high }
let { obs } = env.reset(42);
const r = env.step(1);                    // { obs, reward, terminated, truncated, info: { score, frame, events } }
```

`reward` = 이번 step 점수 변화량(환경 설정의 "점수를 AI 보상으로" 를 끄면 0) + "AI 에게 보상 주기" 블록으로 준 보상의 합. 점수 변화·보상·게임 종료·충돌·경고·오류는
모두 `info.events` 에 남는다.

## 강화학습

- **브라우저 안에서 학습** (`src/rl/`, 설치 없음, 외부 라이브러리 없음): Web Worker(`src/rl/worker.ts`)에서 돌아 화면이 멈추지 않는다.
  같은 시드면 학습 결과가 같다.
- **알고리즘 4종** — 학습 설계 창에서 고른다:
  - **Q-table** (`qtable.ts`): 관찰을 칸(bins)으로 나눠 상태×행동 표를 Q-학습으로 채운다. 관찰이 적을 때만 (상태 수 = 칸^관찰 수, 20만 개 상한)
  - **DQN** (`dqn.ts`): 경험 재생 버퍼, 목표망, ε-탐욕, Double DQN, Huber 손실, 보상 [-1, 1] 자르기
  - **REINFORCE** (`reinforce.ts`): 여러 판의 할인 보상 합을 정규화한 기준선으로 쓰는 가장 기본적인 정책 경사
  - **PPO** (`ppo.ts`): 정책망·가치망 분리, GAE, clip, 보상 정규화, 여러 환경 동시 수집 (기본값)
- **신경망 설계**: 은닉층 개수(0~6)·크기(4~256)·활성함수(tanh·relu·sigmoid)를 고른다 (`nn.ts`, 순수 TS MLP + Adam).
- **하이퍼파라미터**: 학습 길이, 행동 유지(frame skip), γ, 학습률, 시드(매번/고정), 알고리즘별 고급 설정. 설계는 게임(`Project.training`)에 저장된다.
- **frame skip**: AI 가 고른 행동을 몇 프레임 유지할지. 환경의 `step` 은 명세대로 1프레임이고, 학습기·에이전트가 반복한다.
- **이어서 학습**: 학습이 끝난 AI 에서 "⏩ 이어서 학습" 을 누르면 그 가중치(PPO 는 가치망까지, Q-table 은 표)에서 학습 길이만큼 더 배운다.
  학습 곡선·체크포인트도 이어 붙는다. DQN·Q-table 은 이미 아는 것을 다시 헤매지 않게 ε 를 처음부터 낮게 쓴다.
  알고리즘·신경망 모양·활성함수·Q-table 칸 수가 다르거나 관찰·행동이 바뀌었으면 버튼이 꺼지고 이유를 알려 준다 (`canResume`).
  명령줄: `npm run train -- dino --resume 폴더/agent.json --steps 300000`
- **학습 관찰**:
  - 학습 곡선 (무작위 AI 기준선 포함, 마우스를 올리면 값)
  - **학습 중 실시간 보기**: 학습하는 동안 지금까지 배운 AI(2초마다 최신)가 게임 화면에서 끊김 없이 계속 플레이 (판이 끝나면 바로 다음 판)
  - **체크포인트 다시 보기**: 학습의 0·10·…·100% 시점에 한 판씩 녹화(시드 + 프레임별 행동). 결정론적 엔진이라 똑같이 재현된다.
    칩 하나를 눌러 그 시점 실력을 보거나, "처음부터 이어 보기"로 학습 과정을 한 번에 본다. 속도는 최대 64배.
  - 학습된 AI·학습 기록은 게임과 함께 저장되고, 관찰 이름표·행동이 바뀌면 AI 를, 게임 코드가 바뀌면 녹화를 쓸 수 없다고 알려 준다.
- **화면의 학습된 AI**: PPO 는 온도 0.5 로 뽑고, REINFORCE 는 최선 행동, DQN·Q-table 은 최선 행동 + 2.5% 무작위 (실험으로 정했다).
- **Python 연결** (`python/playgym_env.py`): Node 환경 서버(`scripts/env-server.ts`)를 띄워 표준 입출력으로 reset/step 을
  주고받는 Gymnasium 래퍼. `gymnasium.utils.env_checker.check_env` 통과. Stable-Baselines3 등에 바로 넣을 수 있다.

학습 가능성 실험 결과는 아래 "학습 실험" 절과 `experiments/` 에 있다.

## 내 게임

상단 "📁 내 게임" 창에서 게임을 여러 개 저장·열기·복제·내보내기(JSON)·삭제하고, 예제(또는 빈 게임)로 새 게임을 만든다.
예제는 복사본으로 시작하므로 원본이 바뀌지 않는다. 브라우저 IndexedDB(`src/ui/library.ts`)에 자동 저장되며(썸네일 포함),
게임 이름은 상단에서 바로 바꾼다. 예전 버전의 localStorage 자동 저장은 처음 열 때 "이전에 만들던 게임"으로 옮겨진다.

## 모양 탭과 그림 편집기

블록 편집기 위의 **🎨 모양** 탭 (`src/ui/assetPanel.ts`). 게임마다 "쓰는 모양" 목록(`Project.assets`)이 있고,
여기 있는 모양만 "모양" 블록 드롭다운에 나온다 (`setActiveAssets` / `isActiveAsset`). 블록에서 쓰는 모양은 불러올 때 자동으로 들어간다.
카드의 "태그에 입히기…"는 그 태그의 "모양" 블록을 바꾸거나, 없으면 "게임 시작할 때" 끝에 새로 붙인다.

그림 편집기(`src/ui/pixelCanvas.ts`)는 MakeCode 식 픽셀 편집기. 8~32칸 정사각, 16색 팔레트,
연필·지우개·채우기·스포이트, 되돌리기·뒤집기, **기본 모양에서 시작**(코드로 그린 모양을 픽셀로 바꿔 불러와 고치기).
포인터 이벤트 사이를 Bresenham 직선으로 이어 빠르게 그어도 끊기지 않는다.
그린 그림은 `Project.costumes` 에 문자열로 저장되고, "모양" 블록에서 🖌️ 표시로 고른다 (`api.setCostume(tag, 'px:이름')`).
그림 이름을 바꾸면 그 그림을 쓰는 블록도 따라 바뀐다.

## 보상 보이기

- 게임 화면 위 **🎁 보상** 알약: 이번 판 보상 합 (괄호는 방금 받은 보상). "일어난 일" 로그에도 보상이 (합쳐서) 남는다.
- AI 학습 탭의 **이 게임의 보상 규칙** (`src/blocks/rewards.ts` `describeRewards`): 점수 보상 켜짐/꺼짐 + 이벤트에 붙은
  "AI 에게 보상 주기" 블록마다 한 줄. 보상이 하나도 없으면 경고한다.

## 현재 기능

- **엔진** (`src/engine/`, DOM 의존 없음): 400×300 고정 월드, 스텝 기반 결정론 시뮬레이터,
  AABB 물리(중력·solid 밀어내기·onGround·튕기기), 태그 Behavior 5종, 명세 4.4절 step 순서,
  생성·삭제 지연 처리, 객체 300개 상한, mulberry32 시드 RNG
- **센서 12종**: 위치, 속도, 가장 가까운 대상(방향 필터), **가까운 대상 K개**, 거리, 라이다(slab 레이캐스트, 화면 경계 감지),
  **격자**(주체 주변 또는 화면 전체를 칸으로 나눠 대상 유무), 땅 위, 변수, **개수**, **점수**, **속성**(아무 객체 속성 + 범위).
  모두 정규화·clip, 이름표 붙은 고정 길이 벡터. "AI 시야 보기"를 켜면 라이다·연결선·격자 칸이 화면에 그려진다
- **Behavior 6종**: 중력, 단단함, 화면 안에 머물기, 벽 튕기기, 화면 밖이면 삭제, **화면 반대편으로 이어지기 (seamless)** —
  경계에 걸친 객체는 반대쪽에도 그려진다. 이어지기는 상하좌우(`wrap`) 또는 **좌우만**(`wrap_x` → `api.setBehavior(tag, 'wrap', 'x')`)
- **블록** (`src/blocks/`): 커스텀 35종 + Blockly 기본(논리·수학(sin·cos 포함)·반복·변수). 한국어 라벨,
  "가장 먼저 만든 [태그]"(`api.first`, 뱀 꼬리처럼 오래된 것부터 지울 때),
  태그 카테고리("새 태그 만들기"), 변수는 모두 `api.vars` 에 저장, 난수는 엔진 RNG
- **런타임** (`src/runtime/`): `new Function('api', …)` 컴파일, 반복 10,000회 안전장치,
  문장마다 블록 id 기록 → 오류 시 해당 블록 강조
- **게임 화면** (`src/render/renderer.ts`): 월드 좌표는 400×300 그대로, 그리는 해상도만 **200×150**(🕹️ 레트로, 기본 켬)으로
  그려 `image-rendering: pixelated` 로 늘린다. AI 시야(센서·충돌 사각형)는 위에 겹친 다른 캔버스(`#game-ov`)에 화면 해상도로 그려 선명하다.
  그리는 순서는 **태그가 처음 나타난 순서** (먼저 만든 태그가 아래) — 나중에 만든 배경용 객체가 주인공을 가리지 않게.
- **크기 조절 선** (`src/ui/splitters.ts`): 블록|게임 세로 선, 게임/아래 패널 가로 선. 위치는 localStorage 에만 (두 번 누르면 처음대로).
  점수·보상·프레임 칸과 플레이 버튼은 폭을 고정했다 — 글자 폭이 바뀌어 줄바꿈이 달라지면 게임 화면 크기가 출렁였다.
- **게임 카드는 세 줄**: 점수·보상·프레임 + 레트로·AI 시야 토글 / 플레이 버튼들 + 속도 / 조작 키 + 시드. 1366×768 에서도 한 줄씩 들어가게 맞췄고, 남는 높이는 모두 게임 화면에 준다.
- **UI**: 둥근 블록(zelos), 3분할(블록 / 게임 화면 / AI가 보는 값·AI 학습·일어난 일 탭), 플레이·랜덤 AI·학습된 AI·처음부터·한 칸·
  속도(0.25×~64×)·AI 시야·시드·내 게임·키 설정·모양 탭, 누른 키(또는 AI 가 고른 행동)에 불 들어오는 조작 안내
- **모양·배경 그림** (`src/render/costumes.ts`, `backdrops.ts`): 태그 단위 "모양" 블록(공룡·오리·우주선·슬라임·선인장·파이프·운석·패들·공·벽돌·땅·별·동전)과
  환경 설정의 "배경 그림"(하늘·사막·우주·밤·오락실). 그리기 전용이라 물리·관찰에는 영향이 없고, 충돌은 항상 사각형이다
  ("AI 시야 보기"를 켜면 실제 충돌 사각형이 점선으로 보인다). 그림은 모두 코드로 직접 그린 원본
- **예제 11종**: 공룡 게임, 점핑덕, 블록깨기, 장애물 피하기(4방향) + **Atari 스타일** 우주 침략자(Space Invaders 형),
  핑퐁(Pong 형, 컴퓨터와 5점 내기), 폭탄 받기(Kaboom! 형), 오리 사격장(Carnival 형, 좌우만 이어지는 오리, 3번 빗나가면 끝), 스키 활강(Skiing 형)
  + **막대 세우기**(CartPole-v1 물리, 단 60° 넘게 기울면 끝), **뱀 게임**(6프레임마다 한 칸, 100칸 못 먹으면 끝) — 모두 블록만으로 작성.
  처음 4개는 손으로 쓴 JS 버전(`src/templates/js/`)과 블록 버전이 같은 관찰을 내는지 테스트로 확인

행동은 `없음 · ← · → · ↑ · ↓ · A 버튼 · B 버튼` 중에서 환경 설정 블록에 체크한 것만 쓴다.
키 매핑은 프로젝트마다 저장되며 상단 **⌨️ 키 설정**에서 바꾼다 (한 키는 한 행동에만).
기본값은 화살표 + A 버튼 = `A`·`Space`, B 버튼 = `S`. 점프 게임 예제는 `↑`·`Space`·`W` 가 위,
좌우 게임 예제는 `A`·`D` 도 왼쪽·오른쪽이다. 여러 키가 눌려 있으면 가장 최근 키 하나만 쓴다.

## 명세와 다르게 / 구체화한 부분

- **튕기기 방향**: "부호 반전" 대신 "상대에게서 멀어지는 방향"으로 속도를 정한다. 한 step 에 벽돌 두 개에
  동시에 맞아도 두 번 뒤집혀 원래대로 돌아가지 않게 하기 위해서. 보통 경우엔 부호 반전과 같다.
  화면 벽 튕기기도 같은 방식(경계 안쪽 방향).
- **대상 지정**: 명령·값 블록의 대상 칸에는 `태그 [▼]` / `자신` / `상대` 블록을 끼운다 (`태그` 블록은 8장 표에 없던 것 추가).
- **색 선택**: Blockly 색상 필드는 DOM 이 필요해 Node 에서 템플릿을 만들 수 없어서, 색 견본 그림 드롭다운(24색)으로 대신했다.
- **Behavior 설정 블록**: "화면 벽에서 튕기기"는 드롭다운에서 `모든 벽` / `바닥 제외` 두 항목으로 나눴고, `세기` 칸은 중력일 때만 보인다.
- **떠 있는 블록**: 이벤트·설정 모자 블록에 붙지 않은 블록은 실행하지 않는다 (Scratch 와 같음).
- **중복 설정 블록**: 환경 설정·관찰 설정이 두 개가 되면 나중 것을 비활성화하고 경고를 단다.
- **`reset()` 시드 생략**: 환경 안의 고정 시드 수열에서 꺼낸다 (전역 난수 미사용).
- **블록깨기**: 공-패들 충돌 시 맞은 위치에 따라 x속도를 바꾸는 블록 한 줄을 넣었다 (블록만으로 작성). 공은 패들 쪽으로 출발한다.
- **스프라이트(명세 12장 범위 밖 → 추가)**: 명세의 열린 결정사항이던 "색 사각형 대신 그림"을 넣었다. 단, 이미지 파일이 아니라
  코드로 그린 모양이며 태그에 붙는다(`api.setCostume`). 물리·관찰·결정론에는 영향이 없다.
- **색 입력**: "만들기" 블록의 색이 값 칸이 되어 `무지개 색 [n] 번` 블록을 끼울 수 있다 (블록깨기 줄 색).
- **장애물 피하기**: 위에서만 떨어지던 장애물을 네 방향에서 날아오는 운석으로 바꾸고, 상하좌우 이동 + 360° 라이다(16광선)로 바꿨다.
- **행동 A/B 버튼 추가**: 명세 5장의 5개 행동 뒤에 `a`, `b` 를 붙였다 (인덱스 순서는 그대로 유지). 키 매핑은 `Project.keymap` 에 저장되며 RL 환경과는 무관하다.
- **이벤트 로그**: 매 프레임 점수가 오르는 게임에서 로그가 넘치지 않게 연속된 점수 변화는 한 줄로 합친다. 충돌 이벤트는 로그에 쓰지 않는다(`info.events` 에는 있음).

- **보상 블록 (명세 14장 열린 결정)**: "AI 에게 보상 [n] 주기" 블록. 보상 = 점수 변화 + 보상 블록 합 (점수만 쓰던 기존 프로젝트와 호환).
- **점핑덕 점수**: 파이프가 생길 때 +1 → 파이프 사이 보이지 않는 통과 지점(`gate`, 모양 "안 보임")을 지나면 +1 로 바꿨다.
  학습용으로 보상 블록에서 살아 있는 동안 +0.1, 부딪히거나 화면 밖이면 -1 을 준다.
- **RL 학습 위치 (명세 14장 열린 결정)**: 브라우저(순수 TS PPO, Worker)를 기본으로 하고, Python 은 환경 서버 + Gymnasium 래퍼로 연다.

### 유명한 게임과 Atari 스타일 3종 (`experiments/classics/`, `experiments/snake/`, `experiments/atari3/`)

학습된 AI 는 화면 방식 평균. 기준선은 `scripts/random-baseline.ts` (무작위 행동).

| 게임 | 무작위 | 학습 | 결과 |
| --- | --- | --- | --- |
| 막대 세우기 | 43프레임 (12° 규칙일 때 24) | PPO 30만 (약 1분) | **500 (만점)** — 12° 규칙에서도 500, 20만은 345, Q-table 8칸 30만은 1초에 167 |
| 뱀 게임 | 0.1개 | DQN 150만 (약 2분) | **14.2·18.4개** (시드 2개) — PPO 150만 5.7 (300만 5.4), PPO + "가까워지면 +0.1" 7.8 |
| 폭탄 받기 | 1.4개 | PPO 150만 | **122.8개** (3000프레임 끝까지, 최대 약 125) — DQN 도 119 |
| 스키 활강 | 1.9개 | DQN 150만 (약 4분) | **DQN 15.8 / PPO 6.9** → 기본 DQN |
| 오리 사격장 | 0.9마리 (계속 쏘기 0, 정답 정책 66) | PPO 150만 (약 1분 반) | **41마리** — DQN 6 |

- 뱀은 배고픔 규칙이 없으면 AI 가 **빙빙 돌며 버티기**를 배운다 (최선 행동: 먹이 3개, 2239프레임). 100칸 규칙을 넣었다.
- 뱀·스키·우주 침략자·핑퐁은 DQN 이 PPO 보다 낫다. 폭탄 받기·막대 세우기·공룡처럼 "바로 반응하면 되는" 게임은 PPO 가 빠르다.
- 오리 사격장은 네 번 고쳤다 (`scripts/ducks-oracle.ts` 로 "계속 쏘기"와 정답 정책을 비교):
  1. 총알 40발 + 가까운 오리 3마리 관찰 → 무작위 12.8, 학습 16. 빗나간 총알의 손해(총알이 일찍 떨어짐)가 수백 판단 뒤라 AI 가 못 느낀다.
  2. 한 발에 보상 -0.3 → 너무 아껴서 3000프레임 동안 7~8마리.
  3. 시간제(2000프레임) + 빠른 총알 + 총구 위 레이저 → PPO 는 "계속 쏘기"(46)만 배운다 (정답 정책 66). 빗나가도 손해가 없어서.
  4. **빗나가면 목숨 하나, 3번이면 끝** → 계속 쏘기 0, 무작위 0.9, PPO **41**. 손해가 바로 오니 "노리고 쏘기"를 배운다 — 폭탄 받기와 같은 구조.

### 블록깨기: 남은 벽돌을 보여 주면? (`experiments/breakout/`, `scripts/breakout-variants.ts`)

예제 관찰은 패들 위치·공 위치·공 속도(6개)뿐이라 AI 는 벽돌을 보지 않는다. 공이 패들 어디에 맞느냐로 튀는 각도가 바뀌므로
조준할 수단은 있다. 벽돌 관찰을 더해 PPO(탐험 보너스 0.03)·시드 2개로 비교했다. 화면 방식 점수 (벽돌 32개, 3000프레임).

| 관찰 | 입력 | 150만 | 400만 |
| --- | --- | --- | --- |
| 예제 그대로 | 6 | 25.9 · 27.3 | 27.2 · 20.0 |
| + 패들 위 가까운 벽돌 2개 | 10 | 20.4 · 22.9 | |
| + 화면 5×8 격자 (벽돌) | 46 | 7.7 · 13.8 | 25.2 · 19.3 |
| + 화면 15×8 격자 (벽돌 하나 = 한 칸) | 126 | 2.0 · 2.0 | |

- 벽돌을 보여 줘도 나아지지 않았다. 입력이 많을수록 "공 안 떨어뜨리기"를 배우는 것이 느려지고, 400만이 되어야 겨우 따라온다.
- 벽돌이 많을 때는 아무렇게나 튀어도 잘 맞는다. 조준이 필요한 건 마지막 몇 개뿐이라 그 차이를 배우기엔 신호가 작다.
- → 예제는 그대로 둔다. 수업 소재: "더 많이 보여 준다고 더 잘 배우지 않는다".
